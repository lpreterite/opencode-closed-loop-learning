# 经验管理

> Experience Management — v4

**文档状态**：已发布
**当前版本**：v0.4
**最后更新**：2026-05-13

> **设计原则**：六类知识之间的演变遵循有向无环蒸馏图（DAG），成熟度从 L0 逐级晋升到 L3。

---

## 1. 核心洞察

### 1.1 用户的感知边界

- **任务顺利** → 用户觉得 AI"本来就该这样"，**无感知**
- **任务卡住** → 用户介入指导 → **意识到 AI 缺了什么**

### 1.2 为什么不能用成功来验证

| 场景 | 用户感知 | 能否验证经验 |
|------|---------|-------------|
| AI 顺利解决 | 无感知 | **不能** — 不知道是哪条经验起作用 |
| AI 卡住，用户指导后解决 | 有感知 | **能** — 失败本身就是验证数据 |

**结论**：成功是常态，不需要验证；失败才是数据来源。

---

## 2. 知识演变 DAG

六类知识之间形成有向无环蒸馏图（DAG），不是相互独立的并列关系。

### 2.1 DAG 结构

```
                    ┌─────────────┐
                    │   经历(L0)   │
                    └──────┬──────┘
                           │ 捕获
                           ▼
                    ┌─────────────┐
              ┌─────│   案例(L1)  │─────┐
              │     └─────────────┘     │
              │                         │
         反思感受                   确认因果
              │                         │
              ▼                         ▼
       ┌───────────┐       ┌──────────────────┐
       │  偏好(L2)  │       │ 领域知识(L2)      │
       └───────────┘       └──────┬────────────┘
                                  │
                       案例+领域知识→归纳
                                  │
            ┌───────────┬─────────┼──────────┐
            ▼           ▼                  │
     ┌──────────┐ ┌────────────┐           │
     │方法论(L3)│ │领域工作流(L3)│           │
     │ 通用     │ │ 专业       │           │
     └──────────┘ └────────────┘           │
                                           ▼
                                   ┌──────────────┐
                                   │  反模式(L3)   │
                                   │ ← 多次失败蒸馏│
                                   └──────────────┘
```

### 2.2 DAG 关键性质

| 性质 | 说明 |
|------|------|
| **案例是唯一起点** | 没有经历就没有知识，案例没有上游依赖 |
| **偏好向内生长** | 从案例反思感受而来，关于"我是谁" |
| **领域知识向外确认** | 从案例确认因果而来，关于"世界有什么约束" |
| **方法论和领域工作流从归纳而来** | 案例 + 领域知识 → 归纳出可执行步骤 |
| **反模式是终极蒸馏物** | 跨越流程边界，杠杆最高，需要多个失败案例支撑 |
| **执行产生新经历** | 领域工作流执行 → 新经历 → 回到 L0，形成闭环 |

### 2.3 成熟度阶梯

| 成熟度 | 知识状态 | 物理层对应 |
|--------|---------|-----------|
| L0 | 经历了但没记录 | 在工作记忆中，会话上下文 |
| L1 | 案例被记录 | 按需索引，语义检索可达 |
| L2 | 提炼出偏好 / 领域知识 | 触发加载，遇到相关场景时自动加载标题+摘要 |
| L3 | 归纳出方法论 / 工作流 / 反模式 | 按需展开，需要时才加载全文 |

### 2.4 蒸馏约束（防止过早抽象）

| 蒸馏路径 | 最小支撑条件 | 理由 |
|---------|------------|------|
| 经历 → 案例 | 值得记录 | 不问用户，直接捕获 |
| 案例 → 偏好 | ≥1 案例 + 用户确认 | 偏好涉及自我认知，Agent 无权替用户认定 |
| 案例 → 领域知识 | ≥2 案例 + 因果可复现 + 用户确认 | 单次可能是巧合 |
| 案例+领域知识 → 方法论 | ≥2 不同领域的同型流程 + 用户确认 | 方法论必须跨域成立 |
| 案例+领域知识 → 领域工作流 | ≥3 同类案例 + 用户确认 | 流程需足够实践支撑 |
| 失败案例 → 反模式 | ≥2 不同场景失败 + 共性提取 + 用户确认 | 反模式必须跨场景验证 |

### 2.5 蒸馏时机判断（DAG 版）

| 类型 | 第 1 次 | 第 2 次同类 | 第 3 次同类 | 跨域同型 |
|------|---------|-----------|-----------|---------|
| 案例 | ✅ 直接记录 | 记录 | 记录 | — |
| 偏好 | ❓ 先问用户 | 自动确认 | — | — |
| 领域知识 | 不提炼 | ❓ 问用户 | 自动晋升 | — |
| 方法论 | — | — | — | ❓ 问用户 |
| 领域工作流 | 不提炼 | 不提炼 | ❓ 问用户 | — |
| 反模式 | 不提炼 | ❓ 问用户（不同场景） | — | — |

核心原则：**不中断执行流**——蒸馏是闲时操作，只要用户在做任务就不提蒸馏。

### 2.6 生长路径比喻

```
案例是土壤
  ↓ 向内 → 偏好（芽）      ← 关于"我"
  ↓ 向外 → 领域知识（芽）   ← 关于"世界"
       ↓ 归纳 → 方法论 / 领域工作流（果实）
               反模式（化石）← 终极蒸馏
```

## 3. 经验生命周期

### 3.1 触发时机

当用户纠正 AI 时，触发 /mine：

```
用户纠正 AI
     ↓
AI 意识到自己使用了不合适的经验
     ↓
主动说："这次我用了 xxx 经验但不太匹配，是否需要 /mine 提取一下？"
     ↓
/mine 激活
```

### 3.2 触发信号

| 信号 | 说明 |
|------|------|
| 用户说"不是这样做" | 纠正了 AI 的做法 |
| 用户说"应该先..." | 给出了正确的方向 |
| 用户说"你漏了..." | 补充了遗漏的步骤 |
| 用户说"我来告诉你" | 直接传授方法 |
| AI 意识到经验边界不清 | 主动承认不确定 |

### 3.3 不触发 /mine 的情况

- 简单问答
- AI 顺利解决，用户无感知
- 用户说"可以提取一下" — 这种情况用户不是感知到失败，而是感知到成功想分享，但这是稀有情况

## 4. 失败分析协议

当用户纠正 AI 后，经验矿工执行：

### 4.1 失败点定位

```
识别：
  - AI 在哪个环节卡住？（搜索？理解？实施？验证？）
  - 卡住时的表现？（重复尝试？方向错误？遗漏关键信息？）
  - 用户如何纠正？（提示方向？给出具体方案？纠正理解？）
```

### 4.2 经验问题分类

| 问题类型 | 判断标准 | 处理方式 |
|----------|---------|---------|
| **经验缺失** | 没有可用经验覆盖此类任务 | 新建经验 |
| **经验有误** | 现有经验内容本身错误或过时 | 修正经验内容 |
| **边界不清** | 经验适用范围定义模糊 | 补充适用边界 |
| **应用错误** | 经验本身正确但 AI 使用不当 | 强化应用指南 |

### 4.3 修正记录

每次用户纠正后，更新相关经验的元数据：

```yaml
---
name: <经验名称>
metadata:
  fail_count: <失败次数>
  last_fail: "<最近失败日期>"
  corrections:
    - date: "2026-04-07"
      fail_point: "AI 在第三步遗漏了边界检查"
      user_guidance: "需要先确认输入数据格式"
---
```

## 5. 经验提取流程

### 第一步：识别失败

用户纠正 AI → 识别这是一个失败点。

### 第二步：分析纠正

理解用户纠正的内容：
- 用户为什么这样纠正？（揭示了 AI 的什么盲点）
- 这个纠正是否可以泛化为一条经验？

### 第三步：定位相关经验

- 有相关经验 → 修正 + 记录 fail_count
- 无相关经验 → 新建经验

### 第四步：提取新经验（如有）

按模板创建（状态：draft）

### 第五步：更新索引

在 `experience-index` 中更新条目。

---

## 6. 经验清理机制

| 状态 | 清理条件 | 处理方式 |
|------|---------|---------|
| draft | 超过 30 天未被应用 | 降为 inactive |
| failed | 连续失败 3 次 | 修正或归档 |
| verified | 长期稳定 | 保留 |

---

## 7. SKILL.md 元数据格式

```yaml
---
name: <经验名称>
description: <一句话描述>
metadata:
  category: <分类>
  status: draft | verified | failed
  created: "<创建日期>"
  fail_count: 0      # 失败次数
  last_fail: null    # 最近失败日期
  corrections: []     # 修正记录
---
```
