# 反模式：上下文爆炸

## 识别信号

| 信号 | 说明 |
|------|------|
| 单次 read 超过 10 个文件 | 上下文被撑爆 |
| glob pattern 用 `**/*.ext` 一次性列出大量文件 | 应该分批处理 |
| 用 Bash ls 列出目录内容 | 应该用 glob |
| read 没有明确目标，"先了解项目" | 盲目读取 |

## 规避策略

### 1. 搜索驱动读取

```
错误做法：先读20个文件了解结构
正确做法：grep 定位 → 读关键文件
```

### 2. 分批小量读取

```
每次读取不超过 5 个文件
读完一批，处理完，再读下一批
```

### 3. 用完即弃

```
读取后立即处理，不要积累大量已读文件在上下文里
```

### 4. glob 优先于 ls

```
错误：Bash ls src/ → 读取引入胜的文件
正确：glob "src/**/*.ts" → 选择性读取
```

## 正确做法

### 场景：需要了解项目结构

```
1. glob "**/*.ts" 获取文件列表（不读内容）
2. 根据文件名判断哪些需要深入
3. 只 read 关键文件
4. 处理完一批，再下一批
```

### 场景：需要找某个功能

```
1. grep "功能关键词" 定位文件
2. read 该文件确认
3. 不需要读其他文件
```

## 失败案例

AI 用 `read` 读取了整个项目（50+文件），导致：
- 上下文溢出
- 关键信息被稀释
- 浪费大量 token

正确做法是先搜索定位，再针对性读取。
