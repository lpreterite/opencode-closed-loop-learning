# 反模式：过度编辑

## 识别信号
- 单次任务修改超过 5 个文件
- 改动了用户未要求的文件
- 重构了与任务无关的代码
- 添加了"顺便"的改进

## 规避策略

1. **最小改动原则**
   - 只改必须改的文件
   - 只改必须改的行
   - 不添加用户未要求的额外功能

2. **改动前确认**
   - 列出改动清单
   - 等用户确认后再执行（对于大规模改动）

3. **分离关注点**
   - 如果发现相关问题，告知用户但不顺手修
   - 建议用户另开任务处理

## 正确做法
```
用户要求：修复登录页面的按钮颜色
错误：改了按钮颜色 + 重构了整个登录页面 + 更新了依赖
正确：只改按钮颜色对应的 CSS 值
```
