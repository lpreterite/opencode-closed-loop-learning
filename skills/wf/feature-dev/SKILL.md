# 新功能开发流程

## 第一步：理解需求

1. 明确功能边界（做什么、不做什么）
2. 向用户确认理解是否正确
3. 如有参考实现，Read 参考代码

## 第二步：搜索定位

1. Grep/Glob 找到相关代码位置
2. Read 关键文件，理解现有架构
3. 确认代码风格和约定

## 第三步：规划改动

1. 列出改动清单：文件 → 变更内容 → 理由
2. 确认执行顺序和依赖关系
3. 识别风险点（影响范围大的改动）

## 第四步：实施改动

1. 先改核心逻辑，再改周边
2. 每完成一个文件，确认改动正确
3. 模仿周围代码的风格和约定
4. 不添加用户未要求的额外功能

## 第五步：验证

1. 运行 lint/typecheck（如项目有配置）
2. 运行测试（如项目有测试）
3. 检查边界情况

## 关键原则
- 先读后写，永远不要假设代码内容
- 保持最小改动原则
- 模仿现有代码风格
- 不加注释（除非用户要求）
