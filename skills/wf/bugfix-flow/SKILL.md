# Bug 修复标准流程

## 适用边界

**适用场景：**
- 用户报告了错误/异常
- 程序行为与预期不符
- 需要找到并修复问题

**前置条件：**
- 能够复现问题或看到错误信息
- 有相关代码可以查看

## 第一步：复现与定位

```
1. 理解错误信息
   - 错误类型是什么？
   - 哪行代码报的错？
   
2. 搜索相关代码
   - 用 grep 定位关键词
   - 读取引人入胜的文件确认
```

## 第二步：分析根因

```
1. 追踪数据流
   - 参数从哪里来？
   - 经过哪些处理？
   - 最终在哪里出错？
   
2. 确定根因
   - 不是表象，而是根本原因
```

## 第三步：制定修复方案

```
1. 最小修改原则
   - 改最少代码解决问题
   - 不要过度工程
   
2. 考虑边界情况
   - 这个修复会引入新问题吗？
```

## 第四步：实施修复

```
1. 修改代码
2. 验证修复有效
3. 检查是否有相关测试
```

## 第五步：验证

```
1. 重新执行触发场景
2. 确认错误不再出现
3. 检查日志无新异常
```

## 关键原则

| 原则 | 说明 |
|------|------|
| **最小修改** | 改最少代码，不要趁机重构 |
| **先定位再改** | 不要猜测，搜索确认位置 |
| **验证闭环** | 修复后必须验证 |

## 失败案例

直接修改了看到的错误代码，但没解决根因，导致问题在其他地方重现。
