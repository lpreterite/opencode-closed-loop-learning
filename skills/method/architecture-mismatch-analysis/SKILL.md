# 流程：架构文档与实现不一致分析

## 第一步：获取文档基准

1. 读取架构文档（architecture.md、service-integration-plan.md）
2. 提取关键定义：
   - 技术栈（语言/框架）
   - 目录结构
   - API 端点
   - 模块职责划分

## 第二步：对照代码实现

1. 搜索关键文件路径（文档定义的路径是否存在）
2. 检查 API 端点（路由定义是否匹配）
3. 验证模块结构（目录组织是否一致）

## 第三步：记录偏差

使用表格记录所有发现的不一致：

| 维度 | 文档定义 | 实际实现 | 偏差类型 |
|------|---------|---------|---------|
| 语言 | TypeScript | Go | 语言变更 |
| 路径 | src/gateway/pool.ts | src/pool/pool.go | 路径变更 |
| 端点 | POST /mcp | POST /messages | 端点变更 |

## 第四步：评估影响

1. **严重**：核心功能未实现 → 识别缺失实现
2. **中等**：API 签名变更 → 更新调用方
3. **轻微**：路径重构 → 更新文档

## 第五步：确定行动项

- 优先处理严重偏差（缺失功能）
- 中等偏差需要对齐实现和文档
- 轻微偏差可接受但应记录

## 关键原则

- 文档可能过时，代码是真实实现的来源
- 偏差不一定是错误，可能是演进中的文档滞后
- 任何改动都应同步更新文档和代码
